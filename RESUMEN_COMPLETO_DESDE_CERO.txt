📌 ¿QUÉ ES REVIT?
───────────────────────────────────────────────────────────────────────────────
Revit es un software de arquitectura, ingeniería y construcción (AEC) de Autodesk
que permite crear modelos 3D de edificios y estructuras. Es muy utilizado en 
empresas de diseño y construcción.

Un plugin (complemento) es una aplicación que se integra en Revit para agregar
funcionalidades personalizadas que no vienen de fábrica.


📌 ¿QUÉ HICIMOS?
───────────────────────────────────────────────────────────────────────────────
Desarrollamos un plugin personalizado llamado "MI-Exportador de Vistas" que:
• Se integra en Revit 2025
• Agrega un botón con el branding de M.I. Studio
• Permite exportar planos de manera automatizada
• Se puede distribuir automáticamente a compañeros

ETAPA 2: RESOLUCIÓN DE CONFLICTOS DE COMPATIBILIDAD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ Problema identificado:
   Revit 2025 tiene dependencias de .NET 8, pero nuestro proyecto usa .NET 4.8
   Esto causaba conflictos de versiones

🔧 Soluciones aplicadas:

   CONFLICTO 1: System.Net.Http
   ├─ Versión en .NET 4.8: 4.2.0.0
   ├─ Versión que necesita Revit: 8.0.0.0
   └─ Solución: App.config con binding redirect

   CONFLICTO 2: PresentationCore
   ├─ Versión en .NET 4.8: 4.0.0.0
   ├─ Versión que necesita Revit: 8.0.0.0
   └─ Solución: App.config con binding redirect

   Archivo App.config creado:
   <?xml version="1.0" encoding="utf-8"?>
   <configuration>
	 <runtime>
	   <assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
		 <dependentAssembly>
		   <assemblyIdentity name="System.Net.Http" ... />
		   <bindingRedirect oldVersion="0.0.0.0-8.0.0.0" newVersion="4.2.0.0"/>
		 </dependentAssembly>
		 <dependentAssembly>
		   <assemblyIdentity name="PresentationCore" ... />
		   <bindingRedirect oldVersion="0.0.0.0-8.0.0.0" newVersion="4.0.0.0"/>
		 </dependentAssembly>
	   </assemblyBinding>
	 </runtime>
   </configuration>

✅ Resultado: Proyecto compila sin errores


ETAPA 3: IMPLEMENTACIÓN DEL PLUGIN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Basado en la guía oficial de Autodesk para desarrollar plugins, se crearon
dos clases principales:

CLASE 1: Class1 (IExternalApplication)
   Interface requerida: IExternalApplication
   ├─ Método OnStartup()
   │  └─ Se ejecuta cuando Revit inicia
   │     • Crea un panel en la pestaña "Add-Ins"
   │     • Agrega un botón para ejecutar comandos
   │     • Carga el logo de la compañía
   │
   └─ Método OnShutdown()
	  └─ Se ejecuta cuando Revit se cierra

CLASE 2: MyTest (IExternalCommand)
   Interface requerida: IExternalCommand
   └─ Método Execute()
	  └─ Se ejecuta cuando el usuario hace clic en el botón

Código clave:
using Autodesk.Revit.Attributes;
using Autodesk.Revit.DB;
using Autodesk.Revit.UI;

public class Class1 : IExternalApplication
{
	public Result OnStartup(UIControlledApplication application)
	{
		// Crear panel y botón
		RibbonPanel ribbonPanel = application.CreateRibbonPanel("M.I. Studio");

		// Agregar botón
		PushButtonData buttonData = new PushButtonData(...);
		PushButton pushButton = ribbonPanel.AddItem(buttonData) as PushButton;

		// Configurar tooltip y logo
		pushButton.ToolTip = "Exportador de Planos MI";
		pushButton.LargeImage = new BitmapImage(new Uri(logoPath));

		return Result.Succeeded;
	}

	public Result OnShutdown(UIControlledApplication application)
	{
		return Result.Succeeded;
	}
}

✅ Resultado: Plugin funcional


ETAPA 4: REFACTORIZACIÓN DE ESTRUCTURA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ Problema inicial:
   La clase MyTest estaba anidada dentro de Class1:

   public class Class1 : IExternalApplication
   {
	   public class MyTest : IExternalCommand  // ❌ Anidada
	   {
		   ...
	   }
   }

   Esto causaba que Revit no pudiera encontrar la clase completa porque el
   nombre completo era "MYREVITPLUGIN.Class1+MyTest" (con el símbolo +)

🔧 Solución:
   Se movió MyTest fuera de Class1 para que sea una clase independiente

   public class Class1 : IExternalApplication { }

   public class MyTest : IExternalCommand { }  // ✅ Independiente

   Ahora el nombre completo es: "MYREVITPLUGIN.MyTest"

✅ Resultado: Plugin se carga correctamente en Revit

ETAPA 6: INTEGRACIÓN DEL LOGO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ Problema:
   La imagen del logo era demasiado grande (1877 x 2293 píxeles) y Revit
   requiere iconos de tamaño específico (32x32 y 16x16 píxeles)

🔧 Solución:
   Se creó un script Python que redimensiona automáticamente:

   from PIL import Image

   img = Image.open("logo_original.png")

   # Crear versión grande (32x32)
   large_img = img.resize((32, 32), Image.Resampling.LANCZOS)
   large_img.save("logo_large.png")

   # Crear versión pequeña (16x16)
   small_img = img.resize((16, 16), Image.Resampling.LANCZOS)
   small_img.save("logo_small.png")

📍 Ubicación de imágenes:
   bin/Debug/logo_large.png (32x32 píxeles)
   bin/Debug/logo_small.png (16x16 píxeles)

📝 Código que carga las imágenes:
   string logoLargePath = Path.Combine(assemblyDirectory, "logo_large.png");
   string logoSmallPath = Path.Combine(assemblyDirectory, "logo_small.png");

   BitmapImage largeBitmapImage = new BitmapImage(new Uri(logoLargePath));
   BitmapImage smallBitmapImage = new BitmapImage(new Uri(logoSmallPath));

   pushButton.LargeImage = largeBitmapImage;  // Icono grande
   pushButton.Image = smallBitmapImage;       // Icono pequeño

✅ Resultado: Logo visible correctamente en Revit
